# Hovering a big hub is smooth again

## What changed

- `web/src/map/renderer.ts`: the hot dot's neighbours are batched per kind, colour, alpha and
  outline (cached like the resting dots, rebuilt per frame only in Orbit), and pulses are stroked
  one path per colour. One blurred draw per batch instead of one per dot or pulse.
- New perf check `web/e2e/hub-map-perf.spec.ts`: focuses the biggest hub of the 5,000-item map at
  dpr 2 with GPU rasterisation; p95 under 20 ms, longest under 100 ms. Frame helpers moved to
  `web/e2e/frames.ts`.
- Measured in headed Chrome: ~250 ms a frame before, 16.7 ms after; same look (screenshots
  compared). Merged as `ccb7a33` (task `40f6725`).
- Gotcha 10 recorded: headless Chrome draws canvas in software and cannot see this cost.

## Why

Danijel reported that hovering "sessions", the largest group in the imported DRA vault, made the
map slow and choppy. Each of ~560 blurred draw calls was a separate GPU pass.

## How to test (for the user)

1. Pull `develop`; run `pnpm dev:web` (or deploy `develop` to the site first).
2. Open the Map in Rings on the hive with the full vault.
3. Hover the "sessions" hub: its items light up with the glow and pulses fire along the links,
   with no stutter. Move off and back on: still smooth.
