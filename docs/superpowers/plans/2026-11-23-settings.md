# Settings (Agents, Tokens, Members) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed-in member opens `/settings`, connects an agent and gets its token once,
revokes an agent, and sees the hive's members; the owner adds a member who already has an account.

**Architecture:** No schema change. A server-rendered page reads the member's hive, members,
workspaces and own agents through the member's session. A client component holds the forms, the
revoke question and the token dialog in state and calls three server actions that wrap the
existing database functions `create_agent`, `revoke_agent` and `add_member`.

**Tech stack:** Next.js App Router (`web/`), `@supabase/ssr` and `supabase-js`, CSS Modules
reading the generated theme tokens, node:test with PGlite, Vitest, Playwright.

Spec: [`docs/superpowers/specs/2026-11-23-settings-design.md`](../specs/2026-11-23-settings-design.md).

## Global constraints

- **No migration**, no change to `supabase/migrations/` or `mcp/`. No permission logic in `web/`.
- **The token** returned by `create_agent` goes only into the server action's return value and
  the dialog's state. Never `console.*`, never a URL, never `localStorage`/`sessionStorage`,
  never server-rendered HTML, never a test snapshot of real data. Error logs carry only an
  error's code and message.
- Server actions are public endpoints: check every argument before any query.
- Limits: agent name and member display name 1 to 60 characters after trimming; email at most
  254 characters, exactly one `@`, no whitespace; agents list capped at 200.
- Providers, exactly: `Claude`, `ChatGPT`, `Claude Code`, `Codex CLI`, `Other`. Trust tiers:
  `vendor`, `self_hosted`.
- Tokens only for colour: no literal (`#hex`, `rgb(`, `hsl(`, `oklch(`) outside
  `web/src/theme/` and `web/src/app/globals.css`; every stylesheet using `backdrop-filter`
  carries the `@supports not` fallback (`web/src/theme/usage.test.ts`).
- Sizes from the look: card radius 20 px, `blur(30px) saturate(1.5)`, controls 8 px radius,
  section labels JetBrains Mono 11 px uppercase 0.12em, easing `var(--ease)`. No pills, no
  component library, no Tailwind, no icon library.
- The screen fits one window from 1100 × 560 up; the page never scrolls, the card's content does.
- Dates in UTC via `web/src/vault/format.ts`.
- Load `frontend-design` and read `docs/ui-concept.md` before Task 3. Follow the inbox's
  patterns (`web/src/inbox/`, `web/src/app/inbox/`, `web/src/app/dev/inbox/`,
  `web/e2e/inbox.spec.ts`), including its two-step confirmation with the 500 ms guard.
- Tests first, seen failing. Stage by path; conventional commits (lower-case subject) ending
  with the `Co-Authored-By` line. Subagents in a parallel batch do not commit.

## Contracts shared between tasks

`web/src/settings/types.ts` (Task 1 produces; all consume), in full:

```ts
export const PROVIDERS = [
  "Claude",
  "ChatGPT",
  "Claude Code",
  "Codex CLI",
  "Other",
] as const;
export type Provider = (typeof PROVIDERS)[number];
export type TrustTier = "vendor" | "self_hosted";
export type AgentStatus = "active" | "revoked" | "expired";

export type Agent = {
  id: string;
  name: string;
  /** Free text in the database; older agents may carry a value outside PROVIDERS. */
  provider: string;
  trustTier: TrustTier;
  workspaceId: string;
  /** ISO timestamps. */
  createdAt: string;
  lastUsedAt: string | null;
  status: AgentStatus;
};

export type Workspace = { id: string; name: string };
export type Member = {
  id: string;
  name: string;
  role: "owner" | "member";
  isMe: boolean;
};

export type SettingsData = {
  hiveName: string;
  isOwner: boolean;
  workspaces: Workspace[];
  agents: Agent[];
  members: Member[];
};

export type NewAgent = {
  name: string;
  workspaceId: string;
  provider: Provider;
  trustTier: TrustTier;
};

export type Result = { ok: boolean };
export type Created = { ok: true; token: string } | { ok: false };
export type AddReason = "no-account" | "already-member" | "failed";
export type Added = { ok: true } | { ok: false; reason: AddReason };

export type SettingsActions = {
  createAgent(input: NewAgent): Promise<Created>;
  revokeAgent(id: string): Promise<Result>;
  addMember(email: string, name: string): Promise<Added>;
};
```

## Execution DAG

- **Edges:** Task 2 → Task 1. Task 3 → Task 1. Task 4 → Tasks 2 and 3.
- **Batch A:** Task 1.
- **Batch B (parallel):** Task 2 ∥ Task 3 — `web/src/app/settings/` and `tests/` against
  `web/src/settings/Settings.tsx`, `TokenDialog.tsx`, the stylesheet, `/dev/settings` and the

- **Critical path:** Task 1 → Task 3 → Task 4.
- All in the one `task/settings` worktree; tasks in a batch touch disjoint files and do not
  commit; the orchestrator commits each task's paths after reviewing it.

## Performance and data-fetching budget

- **First paint:** hive lookup, then members, workspaces and agents in `Promise.all`, with the
  inbox count alongside. Agents capped at 200, newest first; members and workspaces are small by
  nature. No note or file table is touched.
- **Create, revoke, add:** one rpc, then `router.refresh()`. Forms, the revoke question and the
  dialog are client state: 0 round trips.
- `agents` has no index on `member_id` (a handful of rows per member); accepted in the spec.
- No tabs, filters or sorts.

## Out of scope

Invitations and sign-up, token expiry, renaming, removing members, role changes, workspaces
management, sharing defaults, the audit log, any migration, any MCP change.
