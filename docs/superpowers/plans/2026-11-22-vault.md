# The vault and sharing controls — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** a signed-in member reads their notes at `/vault` and decides, per note or per folder, who
else may read them.

**Architecture:** one migration makes folder rules resolve by path, stops agents moving notes, and
audits every sharing change; the database also reports each note's effective sharing and the exact
reach of a folder rule. The page is server-rendered with the selection in the URL; writes are
server actions that send only the person's decision. Tree, marks and sentences are pure TypeScript.

**Tech stack:** Postgres (PGlite tests), Next.js 16 App Router, React 19, `@supabase/ssr`, CSS
Modules, `react-markdown` + `remark-gfm`, Vitest, Playwright.

**Spec:** [`../specs/2026-11-22-vault-design.md`](../specs/2026-11-22-vault-design.md). Read it
first; this plan does not repeat its reasoning.

## Global constraints

- Sharing is decided in the database. `web/` never computes who can read what: it shows
  `note_visibility`, `note_shared_with`, `note_rule_folder` and `note_access` as returned, and
  writes the person's decision.
- No agent path may change sharing, including by changing a note's `path`.
- Every sharing change by a person writes exactly one `audit_log` row; no audit row ever holds a
  note's path, title or body.
- Migration minted with `scripts/new-migration.sh folder_rules_by_path`; shipped migrations are
  not edited (`create or replace` in the new one).
- Note text is untrusted: rendered by `react-markdown` with raw HTML off, never
  `dangerouslySetInnerHTML`; remote images are not loaded.
- The page is exactly one window tall at desktop sizes; columns scroll on their own.
- `web/` never reads the root `.env`; `SUPABASE_JWT_SECRET` and `service_role` never appear under
  `web/`. `pnpm build` passes with no environment set.
- Look: tokens of `docs/ui-concept.md` §2 and the existing `web/src/map/map.module.css`; load
  `frontend-design` before Tasks 3 and 4. No shadows, no borders on controls, no component
  library, no Tailwind. No invented content.
- Stage by path; conventional commits ending with the `Co-Authored-By` line. Subagents in a
  parallel batch do not commit; the orchestrator commits each task's paths.

## Contracts shared between tasks

**Database (Task 1 produces; Tasks 2–4 consume).**

- `public.note_visibility(n public.notes) returns public.visibility` and
  `public.note_shared_with(n public.notes) returns uuid[]` — replaced, same signatures.
- `public.note_rule_folder(n public.notes) returns text` — path of the rule folder, or null.
- `public.note_access(n public.notes) returns text` — `'own'` when the note is the caller's;
  `'shared'` when its effective visibility is `group`, or `members` including the caller;
  `'link'` otherwise (readable only through an accepted link).
- `public.folder_share_preview(p_workspace uuid, p_path text) returns jsonb` —
  `{ "follows": int, "own_setting": int, "under_nested_rule": int, "held": int }`; raises
  `'for people only'` for an agent identity and `'not your workspace'` otherwise.
- All four are selectable through the API; the first four as computed columns on `notes`
  (`select=id,…,effective:note_visibility,effective_with:note_shared_with,rule_folder:note_rule_folder,access:note_access`).

**TypeScript (Task 2 produces in `web/src/vault/types.ts`).**

```ts
export type Visibility = "private" | "group" | "members";
export type Choice = { visibility: Visibility | null; shared_with: string[] }; // null = no own setting
export type VaultNote = {
  id: string;
  workspace_id: string;
  member_id: string;
  path: string;
  title: string;
  updated_at: string;
  by_agent: boolean;
  visibility: Visibility | null;
  shared_with: string[];
  quarantined: boolean;
  effective: Visibility;
  effective_with: string[];
  rule_folder: string | null;
  access: "own" | "shared" | "link";
};
export type FolderRule = {
  path: string;
  visibility: Visibility | null;
  shared_with: string[];
};
export type Tab = { kind: "workspace"; id: string } | { kind: "shared" };
export type VaultData = {
  hive: { id: string; name: string };
  me: string; // the caller's member id
  members: { id: string; display_name: string }[]; // everyone in the hive, including me
  workspaces: { id: string; name: string }[];
  tab: Tab;
  folders: FolderRule[]; // folder records of the open workspace; empty on the shared tab
  notes: VaultNote[];
  truncated: boolean;
  open:
    null | { note: VaultNote; body: string; cut: boolean } | { missing: true };
};
export type SharePreview = {
  follows: number;
  own_setting: number;
  under_nested_rule: number;
  held: number;
};
export type Result = { ok: true } | { ok: false };
export type VaultActions = {
  saveNote(noteId: string, choice: Choice): Promise<Result>;
  saveFolder(
    workspaceId: string,
    path: string,
    choice: Choice,
  ): Promise<Result>;
  release(noteId: string): Promise<Result>;
  preview(workspaceId: string, path: string): Promise<SharePreview | null>;
};
```

## Review focus

1. A folder whose path is a prefix of a sibling's name (`clients/ac` vs `clients/acme`), or that
   contains `%` or `_`, captures only its own notes (Task 1).
2. A note whose text carries `<script>`, an `<img onerror>`, a `javascript:` link or a remote
   image runs nothing and fetches nothing (Task 3).
3. A forged server-action call — a malformed id, a visibility outside the three values, a member
   id from outside the hive — is refused before or by the database and changes nothing (Task 4).
4. Sentences read correctly for one note, zero affected notes and a hive of one person (Task 2).
5. A refused or failed save leaves the control on its previous state and says so; `?note=` for a
   note the person cannot read shows "That note isn't available." (Tasks 3 and 4).

Rules the signatures do not determine:

- Rule folder = the `folders` row with `workspace_id = n.workspace_id`, `visibility is not null`
  and `left(n.path, length(path) + 1) = path || '/'`, longest `path` first. Case-sensitive.
- `note_shared_with`: the note's own list when `n.visibility is not null`; else the rule folder's
  list; else `'{}'`.
- `folder_share_preview` counts notes of that workspace under `p_path` (same prefix test):
  `follows` = no own setting and no rule folder strictly below `p_path`; `own_setting` = own
  setting; `under_nested_rule` = no own setting but a nearer rule folder; `held` = quarantined
  among `follows`.
- Audit rows: `action` is `note.sharing`, `note.released` or `folder.sharing`; `member_id` = the
  acting person's member in that hive; `agent_id` null; `note_id` set for note rows;
  `detail` = `{"from": {"visibility", "shared_with"}, "to": {…}}` for a note,
  `{"path", "from", "to"}` for a folder, `{}` for a release. Written only when
  `auth.uid()` is not null and the values actually changed (or an insert carries a non-null
  `visibility`). `audit_log` gets no new policy: the triggers are security definer.
- New functions: `security definer`, `stable` where they only read, `search_path = ''`,
  execute revoked from `public, anon` and granted to `authenticated`.

```ts
// tree.ts
export type TreeNode = {
  path: string;
  name: string;
  count: number;
  rule: FolderRule | null;

};
export function buildTree(notes: VaultNote[], folders: FolderRule[]): TreeNode; // root: path "", name ""
export type Scope =

export function notesIn(
  notes: VaultNote[],
  scope: Scope,
  filter: string,

// marks.ts
export type Mark = {
  kind: "private" | "members" | "group";
  from: string | null;
  label: string;
};
export function noteMark(n: VaultNote, members: VaultData["members"]): Mark;
export function folderMark(
  rule: FolderRule | null,
  members: VaultData["members"],
): Mark | null;
// sentences.ts
export function people(names: string[]): string; // "Ahmed", "Ahmed and Sara", "Ahmed, Sara and Lina"
export function noteSentence(a: {
  choice: Choice;
  hive: string;
  hiveSize: number;
  names: string[];
  folderRule: Mark | null;
}): string;
export function folderSentence(a: {
  folder: string;
  choice: Choice;
  hive: string;
  hiveSize: number;
  names: string[];
  preview: SharePreview;
}): string;
export function releaseSentence(mark: Mark): string;
// fixture.ts
export function fixtureVault(now: number): VaultData; // deterministic
export const HOSTILE_BODY: string;
```

Rules:

- `buildTree`: folders come from every directory of every note path plus every folder record;
  `count` is the number of notes at or below; children sorted by name; held notes are counted.
- `notesIn`: `folder` = notes at or below the path; `held` = `quarantined`; `filter` matches title
  or path, case-insensitively; result sorted by path.
- `noteMark` uses only `effective`, `effective_with`, `visibility` and `rule_folder`: `from` is
  the rule folder's path when `visibility` is null and `rule_folder` is set. Labels: "Private",
  "Everyone", "Ahmed and Sara" (names from `effective_with`; an id not in `members` is
  "someone").
- Sentences (exact copy):
  - note, private: "Only you will be able to read this note, and anyone whose link to it you accepted."
  - note, group: "Everyone in {hive} ({n} people) will be able to read this note."; with one
    person in the hive: "Everyone in {hive} will be able to read this note. You are the only
    member so far."
  - note, members: "{people} will be able to read this note."
  - note, same as folder: "This note will follow its folder: {folder label}."
  - folder, group: "Everyone in {hive} ({n} people) will be able to read the {follows} notes in
    {folder}, and any note added there later, including by your agent." (singular: "the 1
    note"); then, when non-zero, " {own_setting} notes with their own setting are not affected."
    and " {under_nested_rule} notes in folders with their own rule are not affected." and
    " {held} held notes stay hidden until you release them."
  - folder, members: the same with "{people}" as the subject.
  - folder, private: "The {follows} notes in {folder} will be readable only by you, and so will
    any note added there later. A note linked with a colleague's note stays readable to that colleague." plus the same tails.
  - folder, no rule: "{folder} will have no rule of its own. Its {follows} notes follow the
    folder above, or your default setting."
  - release: "This note was written by a self-hosted agent. Releasing it makes it follow its
    sharing setting: {label}."
- `fixtureVault`: one hive "Synapse", 3 members, 2 workspaces, about 60 notes across nested
  folders, two folder rules (one `group`, one `members`), notes with their own setting, 2 held
  notes, shared notes from two colleagues (one `access: "link"`), one open note whose body is
  `HOSTILE_BODY`: real markdown (headings, a table, a list, a link) plus `<script>alert(1)</script>`,
  `<img src=x onerror=alert(1)>`, `[click](javascript:alert(1))` and
  `![pixel](https://example.invalid/pixel.png)`.

- Layout: one window tall from 1100 × 560 up (the same approach as the map's fit rule); below

- Accessibility: tabs are links with `aria-current`; the folder list is a nested list of buttons

- Produces:

```ts
// load-vault.ts
export type VaultLoad =
  { state: "ok"; data: VaultData } | { state: "no-hive" } | { state: "error" };
export async function loadVault(
  db: Pick<SupabaseClient, "from" | "rpc" | "auth">,
  query: { ws?: string; tab?: string; note?: string },
): Promise<VaultLoad>;
// validate.ts — pure, no I/O
export function isUuid(v: unknown): v is string;
export function cleanPath(v: unknown): string | null; // 1..500 chars, no leading/trailing slash, no empty or ".." segment
export function cleanChoice(v: unknown, allowed: string[]): Choice | null; // members must be non-empty and ⊆ allowed
```

Rules:

- `loadVault` reads, in this order and nothing else: the hive (`hives`, `limit 1`, oldest); in
  parallel `members` of that hive (`id, display_name, user_id`), own `workspaces`
  (`id, name`, by `created_at`); the caller's user id from `db.auth.getUser()` to find `me`. Then
  the tab: a workspace tab reads its `folders` (`path, visibility, shared_with`) and its note
  index (`eq("workspace_id", id)`, the columns of the spec §3 with the four computed columns,
  `order("path")`, `limit(2001)` — the extra row only detects truncation); the shared tab reads
  notes with `neq("member_id", me)`, `order("updated_at", desc)`, `limit(500)`. `?note=` adds one
  read of that note (`id, …, body`) by id; a colleague's note switches to the shared tab; no row →
  `open: { missing: true }`; a body over 200,000 characters is cut. The default tab is the first
  workspace. Bodies are never selected in an index read. Only error code and message are logged.
- `actions.ts` (`"use server"`): `saveNote`, `saveFolder`, `release`, `preview`, matching
  `VaultActions`. Each validates with `validate.ts` (members allowed = the hive's member ids
  except the caller), then writes with the person's session: `saveNote` =
  `update({ visibility, shared_with }).eq("id", id).select("id")`; `saveFolder` = `upsert` on
  `(workspace_id, path)` with the `member_id` read from the caller's own `workspaces` row;
  `release` = `update({ quarantined: false })`; `preview` = `rpc("folder_share_preview")`. Zero
  rows changed or any error → `{ ok: false }`. No permission logic: the database decides.
- `page.tsx`: dynamic; `no-hive` and `error` use `Notice` with the map's copy
  ("Couldn't load the hive." + "Try again" to `/vault`); `ok` renders
  `<Vault data now actions />`.
- Map: a selected readable note's detail rail gains a link "Open in vault" to
  `/vault?note=<id>`; locked notes, files, hubs and agents do not.

## Performance and data-fetching budget

- **First paint of `/vault`:** the proxy's `auth.getUser`; then `hives` (`limit 1`); then
  `members`, `workspaces` and `auth.getUser` in parallel; then the tab's `folders` and note index
  in parallel (index: named columns, no bodies, one workspace, `limit 2001`, served by the unique
  `(workspace_id, path)` index); plus one body read by primary key when `?note=` is set.
- **No round-trip:** opening folders, choosing a folder, the filter, opening the control on a
  note, composing its sentence.
- **One read:** opening the control on a folder (`folder_share_preview`, one indexed scan of one
  workspace); choosing a note (navigation; the reads above with one body by id); switching tab.
- **Writes:** one statement per save, then `router.refresh()` of the current page.
- **Bounded:** 2,000 notes per tab, 500 shared notes, 200,000 characters of one body.
