# Inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed-in member opens `/inbox`, sees the link proposals waiting for their answer and
their held notes, and accepts, declines or releases each; the rail shows how many wait.

**Architecture:** One migration adds two partial indexes and two people-only read functions
(`inbox`, `inbox_count`) that reveal about a colleague's note exactly what the map reveals. A
server-rendered page calls `inbox` through the member's own session; a client component shows the
two lists and calls two server actions (`respond_to_link`, the vault's release). The other three
pages fetch `inbox_count` in parallel with their own load and hand it to the rail.

**Tech stack:** Postgres (PGlite in tests), Next.js App Router (`web/`), `@supabase/ssr` and
`supabase-js`, CSS Modules reading the generated theme tokens, node:test, Vitest, Playwright.

Spec: [`docs/superpowers/specs/2026-11-23-inbox-design.md`](../specs/2026-11-23-inbox-design.md).

## Global constraints

- The migration is minted with `scripts/new-migration.sh inbox`; never hand-write the stamp. No
  change to an existing migration, to `respond_to_link`, to any policy or to `mcp/`.
- No permission logic in `web/`: the database decides. No service-role key.
- About a colleague's note the functions return **only** the owner's display name, the topic
  (`note_topic(path)`) and, when `can_read_note` allows, the title. Never body, path or id.
- Both functions refuse an identity with an agent id or the self-hosted claim
  (`inbox is for people`) and a caller who is not a member (`not a member of this hive`).
- Caps: **100** links and **100** held notes per load; totals count everything.
- Server actions are public endpoints: check every argument before any query, answer only
  `{ ok }`, log only an error's code and message.
- Tokens only: no colour literal (`#hex`, `rgb(`, `hsl(`, `oklch(`) outside `web/src/theme/` and
  `web/src/app/globals.css`; no component names a theme. Every stylesheet that uses
  `backdrop-filter` carries the `@supports not` fallback (`web/src/theme/usage.test.ts` checks).
- Sizes from the look: card radius 20 px, `blur(30px) saturate(1.5)`, controls 8 px radius,
  section labels JetBrains Mono 11 px uppercase 0.12em, easing `var(--ease)`. No pills, no
  shadows on controls, no component library, no Tailwind, no icon library.
- The screen fits one window from 1100 × 560 up; the page never scrolls, the card's list does.
- Dates are formatted in UTC from the row's own timestamp (reuse `web/src/vault/format.ts`).
- Load `frontend-design` and read `docs/ui-concept.md` before Task 4. Follow the gallery's
  patterns (`web/src/gallery/`, `web/src/app/gallery/`, `web/src/app/dev/gallery/`,
  `web/e2e/gallery.spec.ts`).
- Tests first, seen failing, in every task. Stage by path; conventional commits ending with the
  `Co-Authored-By` line. Subagents in a parallel batch do not commit; the orchestrator commits
  each task's paths.

## Contracts shared between tasks

The function's answer (Task 1 produces, Task 3 consumes) is the JSON in the spec, §1.

`web/src/inbox/types.ts` (Task 2 produces, Tasks 3, 4, 5 consume), in full:

```ts
export type Tier = 1 | 2 | 3 | 4;

export type LinkItem = {
  id: string;
  tier: Tier;
  /** ISO timestamp of the proposal. */
  createdAt: string;
  /** Whose side proposed it: the person's own agent, or the colleague's side. */
  proposedBy: "mine" | "theirs";
  /** True when the other side has already accepted. */
  theyAccepted: boolean;
  mine: { id: string; title: string; path: string; workspaceId: string };
  /** `title` is null unless the person may already read the note. */
  theirs: { memberName: string; topic: string; title: string | null };
};

export type HeldItem = {
  id: string;
  title: string;
  path: string;
  workspaceId: string;
  agentName: string | null;
  /** ISO timestamp of the last write. */
  updatedAt: string;
};

export type InboxData = {
  links: LinkItem[];
  linksTotal: number;
  held: HeldItem[];
  heldTotal: number;
};

export type Result = { ok: boolean };

export type InboxActions = {
  respondToLink(id: string, accept: boolean): Promise<Result>;
  releaseNote(id: string): Promise<Result>;
};
```

`web/src/inbox/text.ts` (Task 2 produces, Task 4 consumes):

export function tierReason(tier: Tier): string;

// title null:    `a private note of ${memberName} in ${topic}`

## Review focus

- Disclosure: nothing about an unreadable note beyond name and topic.
- Agents refused by both functions; a third member and an outsider get nothing.
- The accept sentence matches `can_read_note` (an accepted link opens both notes to each other).
- Decline needs two steps; a failed action keeps the row.
- A failing `inbox_count` never breaks the map, the vault or the gallery.

- [ ] **Step 3: Mint the migration and write it.** `scripts/new-migration.sh inbox`, then:

```sql
-- The inbox: what waits for a person's own decision in one hive.
--
--   inbox(hive)        the newest 100 link proposals the caller has not answered
--                      and the newest 100 of the caller's held notes, with totals
--   inbox_count(hive)  the two totals added, for the rail
--
-- About the other owner's note a link item says what map_graph already says
-- of a locked dot: the owner's name and the note's topic. The title only when
-- can_read_note lets the caller read it. Never the body, the path or the id.
-- A link with a held note on either side is left out until it is released.
-- People only, like map_graph. Both are security definer, so every read is
-- filtered by p_hive and by the caller's own member id explicitly.

create index links_proposed_idx on public.links (hive_id) where status = 'proposed';
create index notes_held_idx on public.notes (member_id) where quarantined;

create function public.inbox(p_hive uuid) returns jsonb
language plpgsql stable security definer
set search_path = ''
as $$
declare
  v_cap constant integer := 100;
  v_me uuid;
  v_links jsonb;
  v_links_total bigint;
  v_held jsonb;
  v_held_total bigint;
begin
  if public.jwt_agent_id() is not null or public.jwt_is_self_hosted() then
    raise exception 'inbox is for people';
  end if;
  select m.id into v_me from public.members m
   where m.hive_id = p_hive and m.user_id = (select auth.uid());
  if v_me is null then
    raise exception 'not a member of this hive';
  end if;

  with waiting as (
    select l.id, l.tier, l.created_at,
           (mine.id = l.from_note) as from_mine,
           (case when mine.id = l.from_note then l.to_accepted_at
                 else l.from_accepted_at end) is not null as they_accepted,
           mine.id as mine_id, mine.title as mine_title, mine.path as mine_path,
           mine.workspace_id as mine_ws,
           o.display_name as their_name,
           public.note_topic(theirs.path) as their_topic,
           case when public.can_read_note(theirs) then theirs.title end as their_title,
           count(*) over () as total
      from public.links l
      join public.notes mine
        on mine.id in (l.from_note, l.to_note)
       and mine.member_id = v_me and mine.hive_id = p_hive
      join public.notes theirs
        on theirs.id = case when mine.id = l.from_note then l.to_note else l.from_note end
      join public.members o on o.id = theirs.member_id
     where l.hive_id = p_hive
       and l.status = 'proposed'
       and (case when mine.id = l.from_note then l.from_accepted_at
                 else l.to_accepted_at end) is null
       and not mine.quarantined
       and not theirs.quarantined
     order by l.created_at desc, l.id
     limit v_cap
  )
  select coalesce(max(w.total), 0),
         coalesce(jsonb_agg(jsonb_build_object(
           'id', w.id,
           'tier', w.tier,
           'created_at', w.created_at,
           'proposed_by', case when w.from_mine then 'mine' else 'theirs' end,
           'they_accepted', w.they_accepted,
           'mine', jsonb_build_object(
             'id', w.mine_id, 'title', w.mine_title, 'path', w.mine_path,
             'workspace_id', w.mine_ws),
           'theirs', jsonb_build_object(
             'member_name', w.their_name, 'topic', w.their_topic, 'title', w.their_title)
         ) order by w.created_at desc, w.id), '[]'::jsonb)
    into v_links_total, v_links
    from waiting w;

  with held as (
    select n.id, n.title, n.path, n.workspace_id, n.updated_at, a.name as agent_name,
           count(*) over () as total
      from public.notes n
      left join public.agents a on a.id = n.written_by_agent and a.member_id = v_me
     where n.member_id = v_me and n.hive_id = p_hive and n.quarantined
     order by n.updated_at desc, n.id
     limit v_cap
  )
  select coalesce(max(h.total), 0),
         coalesce(jsonb_agg(jsonb_build_object(
           'id', h.id, 'title', h.title, 'path', h.path,
           'workspace_id', h.workspace_id, 'agent_name', h.agent_name,
           'updated_at', h.updated_at
         ) order by h.updated_at desc, h.id), '[]'::jsonb)
    into v_held_total, v_held
    from held h;

  return jsonb_build_object(
    'links', v_links, 'links_total', v_links_total,
    'held', v_held, 'held_total', v_held_total);
end
$$;

create function public.inbox_count(p_hive uuid) returns integer
language plpgsql stable security definer
set search_path = ''
as $$
declare
  v_me uuid;
begin
  if public.jwt_agent_id() is not null or public.jwt_is_self_hosted() then
    raise exception 'inbox is for people';
  end if;
  select m.id into v_me from public.members m
   where m.hive_id = p_hive and m.user_id = (select auth.uid());
  if v_me is null then
    raise exception 'not a member of this hive';
  end if;
  return (
    select count(*)
      from public.links l
      join public.notes mine
        on mine.id in (l.from_note, l.to_note)
       and mine.member_id = v_me and mine.hive_id = p_hive
      join public.notes theirs
        on theirs.id = case when mine.id = l.from_note then l.to_note else l.from_note end
     where l.hive_id = p_hive
       and l.status = 'proposed'
       and (case when mine.id = l.from_note then l.from_accepted_at
                 else l.to_accepted_at end) is null
       and not mine.quarantined
       and not theirs.quarantined
  ) + (
    select count(*) from public.notes n
     where n.member_id = v_me and n.hive_id = p_hive and n.quarantined
  );
end
$$;

revoke all on function public.inbox(uuid), public.inbox_count(uuid) from public, anon;
grant execute on function public.inbox(uuid), public.inbox_count(uuid) to authenticated;
```

## Performance and data-fetching budget

- **`/inbox` first paint:** hive lookup + one `inbox` rpc. Each list capped at 100; proposed
  links found through `links_proposed_idx`, held notes through `notes_held_idx`; joins by primary
  key; no body column read.
- **Accept, decline, release:** one write, then `router.refresh()` (the same two reads). The
  decline question is client state: 0 round trips.
- **Map, vault, gallery:** one more `inbox_count` rpc per page load, in `Promise.all` with the
  page's own load, so the chain is no longer. It returns one integer from the same two indexes.
  On failure the count is 0 and the page is unaffected.
- No tabs, filters or sorts.
