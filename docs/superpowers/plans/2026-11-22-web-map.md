# Web app, sign-in and the map — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** a signed-in member sees the six-view map of their real hive, with colleagues' unshared
items as hollow dots.

**Architecture:** one security-definer database function, `map_graph`, returns the whole graph
with private items already reduced to stubs. A Next.js app in `web/` signs the person in through
Supabase Auth, calls that function once on the server and hands the result to a client map whose
geometry is pure, unit-tested TypeScript.

**Tech stack:** Next.js 16 (App Router), React 19, TypeScript strict, `@supabase/ssr`,
`@supabase/supabase-js`, CSS Modules, `geist`, Vitest, Playwright; Postgres + PGlite tests.

**Spec:** [`../specs/2026-11-22-web-map-design.md`](../specs/2026-11-22-web-map-design.md). Read
it first; this plan does not repeat its reasoning.

## Global constraints

- Sharing is decided in the database. No visibility logic in `web/`; the app draws what
  `map_graph` returns.
- `web/` never reads the root `.env`. Its only environment is `NEXT_PUBLIC_SUPABASE_URL` and
  `NEXT_PUBLIC_SUPABASE_ANON_KEY` in `web/.env.local`. `SUPABASE_JWT_SECRET` and any
  `service_role` key never appear under `web/`.
- `pnpm build` must pass with **no environment set** (CI has none): create Supabase clients inside
  request handlers, never at module load.
- The migration is minted with `scripts/new-migration.sh map-graph`; never hand-write a stamp,
  never edit a shipped migration.
- Visual tokens, shapes and copy come from `docs/ui-concept.md` §2–§3 and `docs/ui/map.dc.html`.
  Load the `frontend-design` skill before Tasks 3, 5 and 6 (AGENTS.md #3). No shadows, no borders
  on controls, no component library, no Tailwind.
- No invented content: nothing on screen that the payload did not supply.
- Text from the hive (titles, paths, names) is data: render as text only, never as HTML.
- Stage by path; commits authored as `Danijel Jovanovic <info@synapse-solutions.ai>`,
  conventional messages, ending with the `Co-Authored-By` line.
- Subagents working in a parallel batch **do not commit**; the orchestrator commits each task's
  paths after reviewing it (one worktree, one git index).

## The payload contract (shared by Tasks 2, 4, 5, 6)

`select public.map_graph($hive)` returns one JSON object. Task 4 mirrors it in
`web/src/map/types.ts` as:

```ts
export type MapPayload = {
  members: { id: string; display_name: string; is_me: boolean }[];
  agents: {
    id: string;
    member_id: string;
    provider: string;
    trust_tier: "vendor" | "self_hosted";
    last_used_at: string | null;
    name: string | null; // only the caller's own agents
  }[];
  nodes: MapNode[];
  links: { from: string; to: string; tier: number; score: number }[];
  truncated: boolean;
};
export type MapNode = {
  id: string;
  kind: "note" | "file";
  topic: string;
  member_id: string;
  updated_at: string;
  locked: boolean;
  // null on a locked node:
  title: string | null;
  path: string | null;
  workspace_id: string | null;
  by_agent: boolean | null;
  // only on the caller's own notes:
  agent_id: string | null;
  // only on a readable file:
  note_id: string | null;
};
```

Locked nodes carry the keys with `null` values (a stable shape), never the real values.

## Review focus

Inputs the spec implies but does not spell out; each has a test in the task named.

1. A note at the root, with a one-segment path, a leading slash or doubled slashes still gets a
   topic and never an empty string (Task 2).
2. A hive with zero items, one item, or more than eight topics lays out with finite positions in
   every view (Task 4).
3. The link in `/auth/confirm?next=…` can only send the person to a path on this site (Task 3).
4. A signed-in person who belongs to no hive, or whose `map_graph` call fails, sees one plain line,
   not an error page (Task 6).
5. A title containing markup or 300 characters is shown as text and cut with an ellipsis (Task 5).

```ts
// types.ts — also exports MapPayload and MapNode from the contract
export type View =
  "rings" | "circle" | "topics" | "links" | "timeline" | "orbit";
export type NodeKind = "root" | "hub" | "note" | "file" | "agent";
export type ModelNode = {
  i: number; // index in MapModel.nodes; root is 0
  id: string | null; // database id; null for root and hubs
  kind: NodeKind;
  topic: number; // index into MapModel.topics; -1 for root and agents
  member: string | null;
  mine: boolean;
  locked: boolean;
  title: string; // "Private note" / "Private file" when locked
  path: string | null;
  updatedAt: number; // epoch ms; 0 for root and hubs
  byAgent: boolean;
  nb: number[]; // neighbours
};
export type MapModel = {
  topics: { name: string; hue: number; count: number }[]; // hue 0..7
  members: { id: string; name: string; isMe: boolean }[];
  nodes: ModelNode[];
  edges: [number, number][]; // structural edges and real links
  linkCount: number; // real links only
  truncated: boolean;
};
export type Filter = {
  topic: number | null;
  kind: NodeKind | null;
  member: string | null;
  q: string;
  sel: number | null;
};
export type Activity = {
  today: number;
  perMember: { id: string; name: string; count: number }[]; // most first
  days: { day: number; member: string; count: number }[]; // agent writes, last 14 days
};

// graph.ts
export const BOX: { w: 1000; h: 760 };
export function buildModel(payload: MapPayload): MapModel;
export function activity(model: MapModel, now: number): Activity;
export function agentStatus(lastUsedAt: string | null, now: number): string;
// layouts.ts
export function layout(
  view: Exclude<View, "orbit">,
  model: MapModel,
  now: number,
): [number, number][];
export function orbit(model: MapModel): [number, number, number][];
// select.ts
export function lit(model: MapModel, f: Filter): boolean[];
// fixture.ts
export function fixturePayload(now: number): MapPayload;
```

Rules the signatures do not determine:

- `buildModel`: topics ranked by item count (ties by name); the seven largest keep hues 0–6 and
  every other topic folds into one topic named `Other` with hue 7; with eight or fewer topics each
  keeps its own. Edges: root → each hub; hub → each item of its topic; a file with a readable
  `note_id` hangs off that note instead of the hub; each payload link; each agent → the hubs
  where it wrote (`agent_id` match; for a colleague's agent, the hubs where that member has
  `by_agent` notes).
- `agentStatus`: `"connected"` within 70 minutes of `now`, `"never used"` for null, otherwise
  `"last used <d Mon>"`.
- `activity.today`: nodes changed in the 24 hours before `now`, locked included.
- `layout("links")`: the prototype's force layout, 170 iterations, started from the `topics`
  positions; the caller caches the result.
- `lit`: the prototype's `lit` rule; search matches the shown title and the topic name,
  case-insensitively, so a locked node never matches on its real title.
- `fixturePayload`: deterministic (seeded), about 300 nodes, 3 members, 10 topics, files, links,
  locked nodes, 4 agents; dates relative to `now`.

## Performance and data-fetching budget

- **First paint of `/`:** one `auth.getUser`, one bounded `hives` query (`limit 1`), one
  `map_graph` call. Nothing else, and nothing from the browser.
- **Interactions** (view, filters, search, selection, labels): 0 round-trips, client state only;
  asserted by the browser test in Task 5.
- **Server data changed:** none in this slice.
- **Bounded and indexed:** `map_graph` reads named columns through `notes_hive_idx` and the new
  `files_hive_idx`, never bodies, capped at 5,000 nodes. Each layout is computed once per view and
  cached in the component; the force layout runs only when "Links" is first opened.
- **Refresh:** on window focus, at most once a minute.
